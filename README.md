# wxedge — เครื่องมือประเมินความน่าจะเป็นสำหรับตลาดอุณหภูมิ Polymarket

**คำตอบสั้น:** มีครับ — API พยากรณ์อากาศที่แม่นพอใช้ได้มีให้ฟรีหลายตัว (ECMWF EPS, GEFS, ICON EPS, NBM, HRRR, NWS, Open-Meteo) และผมได้สร้างเครื่องมือที่ต่อทุกอย่างเข้าด้วยกันแล้วในโฟลเดอร์นี้ (`wxedge.py`) พร้อมตรวจสอบย้อนหลังจริง

> **ความแม่นที่ทำได้จริง:** RMSE ของ daily high ≈ **0.8–1.0 °C (1.5–1.8 °F)** → ตลาด bin กว้าง 2 °F / 1 °C จะทาย bin ถูกประมาณ **40–50%** ต่อวัน (ไม่ใช่ 80–90% แบบที่หลายคนคิด) กำไรมาจาก "ราคา vs ความน่าจะเป็น" ที่คลาดเคลื่อน ไม่ใช่จากการทายถูกทุกวัน

---

## 1) API/แหล่งข้อมูลที่ใช้ (ทดสอบแล้วว่าเรียกได้จริง 23 ก.ย. 2026)

| แหล่งข้อมูล | ให้อะไร | ข้อดี | ข้อระวัง |
|---|---|---|---|
| **Open-Meteo Ensemble API** `ensemble-api.open-meteo.com/v1/ensemble` | สมาชิก ensemble 122 ตัว (ECMWF EPS 51 + GEFS 31 + ICON EPS 40) ของ `temperature_2m_max` รายวัน | ฟรี ไม่ต้อง API key, ได้ทั้งชุดความน่าจะเป็น ไม่ใช่แค่เลขเดียว | ensemble เก็บย้อนหลังได้แค่ ~5 วัน; บางครั้ง error → ต้อง retry |
| **Open-Meteo Forecast API** `api.open-meteo.com/v1/forecast` | พยากรณ์ deterministic: `best_match`, ECMWF IFS/AIFS, ICON, UKMO, JMA, GEM, BOM + **NBM**, **HRRR** (สหรัฐฯ) | NBM = พอยต์ฟอร์แคสต์ที่ดีสุดเชิงสถิติของ NOAA, HRRR แม่นสุด < 18 ชม. | NBM/HRRR ครอบคลุมแค่สหรัฐฯ |
| **NWS** `api.weather.gov` | gridpoint forecast + station observations (US) | ต้นทางราชการ ใช้ตัดสินตลาด US | สถานีนอก US ไม่มีข้อมูล |
| **IEM ASOS** `mesonet.agron.iastate.edu/cgi-bin/request/asos.py` | METAR รายชั่วโมงของสถานีทั่วโลก (`tmpc`) = **ค่าจริง** สำหรับ calibrate | ครอบคลุมสถานีสนามบินทั่วโลก ย้อนหลังยาว | มี rate limit (429) → ต้องเว้น ~2 วินาที/คำขอ + retry |
| **HKO Daily Extract** `hko.gov.hk/cis/dailyExtract/dailyExtract_YYYYMM.xml` | ตาราง "Absolute Daily Max (°C)" ของฮ่องกง (**ไฟล์ .xml แต่ข้างในเป็น JSON**) | เป็นแหล่งที่ตลาดฮ่องกงใช้ตัดสินจริง — ตรงที่สุด | เผยแพร่ล่าช้าเล็กน้อย; อย่าสับสนกับ CLMMAXT ที่ไม่อัปเดตเดือนปัจจุบัน |
| **Polymarket Gamma API** `gamma-api.polymarket.com/events?slug=...` | ราคา yes/no, volume, liquidity ของทุก bin | ใช้เทียบ edge ได้ทันที | ต้องใส่ User-Agent มิฉะนั้น 403 |
| `api.synopticdata.com` | แหล่งข้อมูลเบื้องหลังหน้า WRH ที่ตลาด US อ้างอิงในการตัดสิน | — | ต้องใช้ token ของ NWS → เราใช้ IEM METAR รายชั่วโมงเป็นตัวแทนที่ใกล้เคียง |

### ความแม่นเชิงเปรียบเทียบ (จาก `calibrate` จริง 45 วัน, สถานี KLGA/NYC)

| โมเดล | RMSE (°C) | bias (°C) |
|---|---|---|
| ICON (seamless) | **0.75** | +0.08 |
| GEM (Canada) | 0.79 | +0.18 |
| UKMO | 0.83 | +0.18 |
| HRRR / GFS | 0.87 | +0.59 |
| NBM (NOAA) | 0.88 | −0.37 |
| ECMWF IFS | 1.04 | −0.42 |
| ECMWF AIFS | 2.22 | −1.95 |

→ ที่ระยะ 1–2 วัน: **ECMWF EPS + GEFS/ICON EPS (สำหรับความน่าจะเป็น) + NBM/HRRR (สำหรับ anchor)** คือชุดที่คุ้มที่สุด และ *ต้อง* calibrate bias ต่อสถานี เพราะแต่ละโมเดลมีอคติคนละทาง 0.1–2 °C

## 2) จุดที่คนเล่นตลาดนี้พลาดบ่อยที่สุด: "สถานีที่ใช้ตัดสิน"

ตลาด **"Highest temperature in X on DATE?"** ไม่ได้ใช้ "อุณหภูมิเมือง X" แต่ใช้ **สถานีเฉพาะ** และเกณฑ์วัดเฉพาะ:

| เมือง | สถานีที่ตัดสิน | หน่วย | เกณฑ์ |
|---|---|---|---|
| NYC | **LaGuardia Airport (KLGA)** — ไม่ใช่ Central Park | °F | ค่าสูงสุดของคอลัมน์ Temp บน [WRH hourly](https://www.weather.gov/wrh/timeseries?site=klga) |
| Austin | Austin-Bergstrom (KAUS) | °F | ย้ำในกติกา: ใช้ปุ่ม "Show Hourly Data" (รายชั่วโมง) |
| Miami | KMIA | °F | hourly |
| London | **London City Airport (EGLC)** ไม่ใช่ Heathrow | °C | 1 °C ต่อ bin |
| Paris | **Le Bourget (LFPB)** | °C | |
| Moscow | Vnukovo (UUWW) | °C | |
| Seoul | Incheon (RKSI) / Busan Gimhae (RKPK) | °C | |
| **Hong Kong** | **Hong Kong Observatory (HKO)** — ไม่ใช่สนามบิน | °C | "Absolute Daily Max" ใน Daily Extract |
| Karachi | Jinnah (OPKC) | °C | |

เครื่องมือนี้ดึงค่าสถานีจากกติกาจริงของแต่ละตลาดมาใส่ `stations.json` **50 เมือง** (11 เมืองหน่วย °F / 39 เมืองหน่วย °C) ให้แล้ว — ถ้าเมืองไหนมีตลาดใหม่ ใช้ `python3 build_stations.py` รีเฟรชได้

**โครงสร้าง bin:** ตลาดสหรัฐฯ = bin กว้าง **2 °F** (เช่น 66-67, 68-69) + "57°F or below" / "76°F or higher" / ตลาดอื่น = **1 °C** ต่อ bin + "25°C or below" / "35°C or higher" — ต้องปัดเป็นจำนวนเต็มในหน่วยของตลาดก่อนคิดความน่าจะเป็น (`wxedge` ทำอัตโนมัติ)

## 3) หลักการของเครื่องมือ (`wxedge.py`)

```
ensemble 122 สมาชิก (ECMWF/GEFS/ICON EPS) ─┐
                                          ├─ bias-correct ต่อโมเดล (จาก IEM/HKO ย้อนหลัง 45-60 วัน)
deterministic 12 ตัว (NBM, HRRR, NWS, ├─ anchor: ดึงค่าเฉลี่ย ensemble ให้ตรงจุด
best_match, IFS, AIFS, ICON, UKMO, ...)  ─┘  (น้ำหนัก: NBM 3, NWS 2, HRRR 1.5, best_match 1.5, ...)
                                          ↓
                     residual noise σ = √(RMSE_best² − spread²)  (พื้น 0.4 °C)
                                          ↓
                     Monte-Carlo 20,000 ตัวอย่าง → ความน่าจะเป็นต่อ bin ของตลาด
                                          ↓
  ถ้าเป็น "วันนี้": ใช้ max(ค่าที่วัดได้แล้ว, max ของชั่วโมงที่เหลือจาก ensemble)
                                          ↓
     เทียบราคา yes จริง → edge / EV / Kelly  (Polymarket Gamma API)
```

**หมายเหตุเชิงเทคนิคที่สำคัญ** (และแก้ไว้แล้วในโค้ด)
- daily max ที่คำนวณจากค่า hourly ของโมเดลจะ *ต่ำกว่า* ค่าสูงสุดจริงเล็กน้อย (peak ตกหว่างชั่วโมง) → bias นี้ถูกดูดกลืนไปใน calibration
- ตลาดสหรัฐฯ ตัดสินจาก **ค่า hourly** บนหน้า WRH (ไม่ใช่ค่า 5 นาที) → ใช้ METAR รายชั่วโมงเป็นค่าจริง
- IEM ตอบ HTTP 200 พร้อมข้อความ "Too many requests" → โค้ดตรวจข้อความนี้และ retry (ถ้าไม่ตรวจจะได้ข้อมูลว่างเงียบ ๆ = ทายผิด)
- HKO: ใช้ `dailyExtract_YYYYMM.xml` (แหล่งตัดสินจริง) แทน CLMMAXT ที่ไม่อัปเดตเดือนปัจจุบัน

## 4) วิธีใช้

```bash
cd wxedge

# ดูรายชื่อเมือง/สถานี
python3 wxedge.py stations

# ทำนายเมืองเดียวเทียบราคาตลาด (ค่าเริ่มต้น = วันนี้ตาม timezone ของสถานี)
python3 wxedge.py predict nyc
python3 wxedge.py predict london --date 2026-09-25

# สแกนทุกตลาดที่เปิดอยู่ จัดอันดับ bin ที่ราคาผิด
python3 wxedge.py scan --limit 15 --min-edge 0.05 --min-vol 500 --out reports/scan.md

# วัด bias/RMSE ของแต่ละโมเดลกับสถานีนั้น (แนะนำทำก่อนเทรดเมืองใหม่)
python3 wxedge.py calibrate karachi --days 60

# backtest: ensemble รุ่นย้อนหลัง vs ค่าจริง (hit rate / Brier)
python3 wxedge.py verify --days 5 --cities 16 --out reports/backtest.md
```

**ตัวอย่างผลจริง (NYC, 23 ก.ย. 2026, 17:00 น. local)**

```
LaGuardia Airport (KLGA) | 2026-09-23 | หน่วยตลาด: °F
ensemble: mean 19.08°C spread 0.81 | bias -0.19 | anchor 20.23 | sigma_res 0.40
ค่าจริงวันนี้จนถึง 17:00 น. = 21.1 °C   →  ช่วง 5–95%: 20.9 – 21.3 °C
70-71°F   model 100.0%  vs ตลาด 99.2%   (edge +0.7%)
```

## 5) ผลตรวจสอบย้อนหลัง (backtest) — `reports/backtest.md`

ทดสอบ 16 เมือง × ~3 วัน = **44 วัน-เมือง** (ensemble รุ่นที่เก็บไว้, lead ~1 วัน)

| ตัวชี้วัด | ค่า | หมายเหตุ |
|---|---|---|
| ทาย bin ถูก (top bin) | **39%** | เพดานตามทฤษฎีที่ RMSE 1.5 °F กับ bin 2 °F ≈ 45–50% |
| ความน่าจะเป็นเฉลี่ยที่ให้กับ bin จริง | 29.1% | ไม่ overconfident |
| Brier score | **0.644** | ต่ำ = ดี |

**แยกตามเมือง:** ยุโรปดีมาก (Paris 2/2, Amsterdam 2/2, Munich 2/2, London 2/2, Helsinki 2/3) / สหรัฐฯ ผสม (NYC 2/3, Chicago, Miami, Atlanta ผ่าน) / **แย่ชัดเจน: Seattle, San Francisco, Denver, Los Angeles, São Paulo (0/3)** → เมืองชายฝั่ง/ภูมิประเทศซับซ้อน ต้อง calibrate ต่อเมืองและระวังเป็นพิเศษ

## 6) ข้อควรระวังก่อนเอาไปเทรดจริง

1. **edge ที่เห็น ≠ กำไรฟรี** — ตลาดนี้คล่องตัวสูง ถ้าโมเดลเราเห็น edge 20–30% มักแปลว่า *เราขาดข้อมูลที่ตลาดมี* เช่น พยากรณ์ทางการของประเทศนั้น (HKO/JMA/Met Office), เรดาร์/obs intraday, หรือข่าวพายุ → **ก่อนเทรดให้เช็ค 3 อย่าง:** (ก) พยากรณ์ของหน่วยงานอุตุฯ เจ้าของสถานีนั้น (ข) ค่าที่วัดได้แล้ววันนี้ (ค) รูปแบบอากาศ (เมฆ/ฝน/sea breeze) ที่โมเดลมองไม่เห็น
2. **ระยะที่ทำเงินได้ดีที่สุดคือ lead 1–3 วัน** — พอเป็นวันเดียวกัน ข้อมูล observation จะกลืน edge (ตัวอย่าง Miami/NYC ข้างบน: โมเดล = ตลาด) ส่วน lead 4+ วันความไม่แน่นอนเกิน bin 2 °F ไปมาก
3. **overround/สเปรด**: Σ ราคา yes ทุก bin มัก 0.98–1.01 → ต้องมี edge เกินค่าธรรมเนียม/สเปรด
4. **ความเสี่ยงจากกติกา**: ถ้าข้อมูลต้นทางล่ม ตลาดอาจ resolve เป็น bin ล่างสุด (HK: 7 วัน, Karachi: 1 วัน) — bin สุดขอบไม่ควรซื้อแพง
5. **ขนาดเดิมพัน**: ใช้ Kelly แล้วหาร 2–3 (ตัวอย่าง output มีคอลัมน์ kelly ให้แล้ว) และเช็ค volume ของ bin นั้นก่อน (bin ที่ volume ต่ำ slippage กินกำไร)
6. **ข้อมูล API อาจล่ม/จำกัดอัตรา**: โค้ดมี retry + cache ใน `.cache/` แล้ว แต่ถ้าพยากรณ์ใน cache เก่าเกิน ~15 นาทีให้รันใหม่

## 8) ⭐ ใหม่: วัด "ทาย bucket ถูกจริง" ล่วงหน้า (hit rate) — อัปเดต 23 ก.ย. 2026

## 10) ⭐⭐⭐ ซื้อ bin ราคาถูก (< $0.25) แล้วชนะตอนปิด — ทำได้จริงไหม? (อัปเดต 24 ก.ย. 2026)
