วันที่: 2026-09-24 · ทุกตัวเลขวัดเทียบกับ **bucket ที่ตลาด Polymarket resolve จริง** (ไม่ใช่ค่าประมาณจากสถานี)

## 1. สรุปคำตอบ

| คำถาม | คำตอบ |
|---|---|
| ทำ 70% ได้ไหม? | **ได้** — แต่เฉพาะการทาย **"ระหว่างวัน" หลังผ่านช่วง peak** (≥15:00 น. ตามเวลาท้องถิ่นของสถานี) |
| ตัวเลขจริง (ฐานใหญ่ 85 วัน) | **15:00 → 76.0%** · 16:00 → **85.3%** · 17:00 → 88.5% (n = 4,010 ตลาด-วัน, 48 เมือง, 1 ก.ค.–23 ก.ย. 2026) |
| ตัวเลขรอบแรก (21 วัน) | 15:00 → 79.8%, 16:00 → 87.9%, 17:00 → 90.2% (n = 917) — ใกล้เคียงกัน |
| ทายล่วงหน้า 1 วัน (D-1) ทำได้เท่าไร? | **52.2%** และแม้กรองความมั่นใจสูงสุด (p≥0.65) ก็ได้แค่ **65.0%** → **ห่างจาก 70% จริงในhorizon นี้** |
| มีกำไรจริงไหมตอน 15:00? | ใช่ — ราคา bin ที่จะชนะตอน 15:00 เฉลี่ย **0.627** (มัธยฐาน 0.605) → ถ้าซื้อ bin ที่โมเดลเลือก (ถูก 79.8%) คาดหวัง ~**+28% ต่อไม้** (ยังไม่หัก fee/spread) |

**กติกาเดียวที่ต้องจำ:** *ทายวันที่ตลาดจะปิด ไม่ใช่ทายล่วงหน้า* — รอให้ค่าอุณหภูมิไต่ถึง 15:00 น. ท้องถิ่นก่อน แล้วค่อยทายจากค่า max ที่วัดได้จริงบวกส่วนที่ยังจะเพิ่มอีก

## 2. เปลี่ยนเฉลยจาก "proxy" เป็น "เฉลยจริง" (สิ่งที่แก้ในรอบนี้)

ก่อนหน้านี้ใช้ IEM METAR เป็น label — เป็น **proxy** ซึ่งเป็นเพดานที่ทำให้วัดได้ไม่เกิน ~50%
รอบนี้ดึงเฉลยจากตลาดเอง (`market_labels.py` → `data/market_labels.csv`) ได้ **981 ตลาด-วัน / 50 เมือง (3–23 ก.ย. 2026)** จับคู่กับชุดทำนายได้ **960 แถว**

ตรวจว่า proxy ที่ใช้อยู่ดีแค่ไหน:

| แหล่งข้อมูล | ตรงกับ bucket ที่ตลาด resolve |
|---|---|
| IEM METAR รายชั่วโมง (ที่ใช้อยู่) | **94%** (80/85 เมืองสหรัฐ) — ใช้ได้ |
| NWS 5-min observations (api.weather.gov) | **56%** (43/77) — NWS สูงเกินจริงเฉลี่ย +0.30°F → **ห้ามใช้** |
| label IEM เทียบ label ตลาดทั้ง 960 แถว | 91% ตรงกัน |

> หมายเหตุสำคัญ: "คอลัมน์ WRH/NOAA 5 นาที" ที่ตลาดอ้างในคำตัดสิน *ไม่ใช่* api.weather.gov (ทดสอบแล้วแย่) และใช้งานตรงไม่ได้ (ต้อง mesoToken) → **IEM METAR รายชั่วโมงคือแหล่งที่ใกล้ที่สุดและใช้ได้ฟรี**

ตัวเลข hit rate เมื่อเปลี่ยนมาใช้เฉลยจริง: **top-1 = 52.2%** (เทียบ proxy เดิม 52.6%) → ยืนยันว่าเพดานเดิมไม่ใช่ปัญหาที่ proxy

## 3. สิ่งที่ทดลองแล้ว "ไม่ทำให้ถึง 70%" (บันทึกไว้ไม่ให้ลองซ้ำ)

| แนวทาง | ผล |
|---|---|
| กรองด้วย p ของ bin ที่ดีสุด | p≥0.55 → 62.9% (n=267), p≥0.65 → 65.0% (n=60) → ยังไม่ถึง 70% และเหลือวันน้อยมาก |
| เลือกเฉพาะเมืองที่ทำได้ดี | **overfit ชัดเจน**: เลือกจาก train (3–14 ก.ย.) ได้ 80.2% → วัดกับ test (15–23 ก.ย.) เหลือ **43.5%** |
| ปรับ shift ตามผลต่าง bin center − โมเดล | test 38.2% → 38.0% / ต่อเมือง 35.1% (แย่ลง) |
| `intraday.py --uplift auto` (ชดเชย 5-min vs METAR) | 15:00 ตกจาก 79.8% → **52.8%** (แย่ลงมาก) — สาเหตุ: ค่า median ของ "bin center − ค่าจริง" มีอคติ +0.5 อยู่แล้ว → **ห้ามใช้** |

## 4. กติกาที่ใช้ได้จริง — หัวใจคือ "ช่วงเวลาที่รู้คำตอบแล้ว"

Daily max เกือบทั้งหมดเกิด 13:00–17:00 น. ท้องถิ่น → หลัง 15:00 น. ค่าสูงสุด "เกือบ" ถูกล็อก
ทำนายด้วย: `max(ค่าที่วัดได้ถึงชั่วโมงนั้น) + การกระจายตัวของส่วนที่ยังเพิ่มได้ (จาก 30 วันก่อนของสถานีเดียวกัน)`
สร้างการแจกแจงเป็นความน่าจะเป็นต่อ bin แล้วเลือก bin ที่ p สูงสุด

| ชั่วโมง (local) | ทายถูก (เทียบตลาดจริง) | ถูกใน 2 bin ติดกัน | ข้อสังเกต |
|---|---|---|---|
| 13:00 | 52.7% | 80.0% | ยังไม่ถึงเป้า |
| 14:00 | 61.4% | 87.6% | เกือบ |
| **15:00** | **76.0%** | 92.9% | ✅ ผ่าน 70% — มี **35/48 เมือง** ที่ ≥70% |
| 16:00 | **85.3%** | 93.1% | ปลอดภัยกว่า |
| 17:00 | 88.5% | 91.9% | |
| 18:00 | 91.2% | 91.4% | ราคาตลาดแพงขึ้นมาก |

### แยกตามเมือง (ชั่วโมง 15:00, n=19–20 ต่อเมือง)

**≥90%:** san-francisco, jeddah, taipei 100% · panama-city 95% · miami, istanbul, tel-aviv, houston, qingdao, busan, shenzhen 95%

**80–90%:** buenos-aires, toronto, nyc, denver, chicago, dallas, wellington, seoul, manila, lucknow, mexico-city, los-angeles, sao-paulo

**70–80%:** amsterdam, helsinki, cape-town, shanghai, austin, london, tokyo, kuala-lumpur, guangzhou, chengdu, karachi

**<70% ที่ 15:00 (เลื่อนไปทาย 17:00–18:00 แทน):** atlanta 68.4, beijing 68.4, warsaw 68.4, ankara 68.4, singapore 68.4, chongqing 68.4, wuhan 68.4, munich 63.2, seattle 63.2, milan 57.9, moscow 47.4, **madrid 42.1, paris 36.8**

> กลุ่มนี้พลาดเพราะ **peak เกิดช้า** (นิยม 16:00–18:00) — ที่ 15:00 ค่าจริงยังไม่ล็อก ลองทายใหม่ตอน 17:00:
> atlanta 100% · seattle/warsaw/wuhan 94.7% · **paris/milan/ankara/moscow/chongqing 84.2%** · beijing/munich/singapore 78.9% · **madrid ยังแย่ 52.6% → ต้องรอถึง 18:00 (ได้ 94.7%)**

## 7. ข้อจำกัดที่ต้องพูดตรง ๆ

1. **ช่วงเวลาสำคัญ**: 70%+ เกิดเฉพาะช่วง 15:00 ขึ้นไปของวันนั้น — ก่อนหน้านั้นความไม่แน่นอนสูงจริง (13:00 = 52.7%) อย่าใช้กติกานี้ตอนเช้า
2. จำนวนวันเฉลย = 21 วัน (3–23 ก.ย. 2026) ต่อเมือง — n รวม 917 ตลาด-วัน พอเชื่อได้ แต่ควรเก็บต่อทุกวัน (รัน `market_labels.py --mode page` เพิ่มวันละครั้ง)
3. ราคา/EV ยังไม่หัก fee, spread, และ slippage; ราคาตลาดขยับได้ทุกนาที
4. IEM archive ใน sandbox หน่วง ~1 วัน (มีข้อมูลถึง 22 ก.ย.) — ในงานจริงข้อมูล METAR รายชั่วโมงมีภายใน ~20–60 นาทีหลังชั่วโมงนั้น จึงใช้ `--live` ได้ทันที
5. เมืองที่ peak ช้า (paris, moscow, milan, seattle, beijing, singapore, atlanta, warsaw, ankara, wuhan, chongqing) ให้ใช้ 17:00 — ส่วน **madrid ต้องรอ 18:00** (17:00 ยังได้แค่ 52.6%)
6. อย่าใช้ NWS 5-min (api.weather.gov) เป็น obs — ตรงกับตลาดแค่ 56%
7. อย่าใช้ `--uplift auto` (ทดลองแล้วแย่ลง 52.8%)
